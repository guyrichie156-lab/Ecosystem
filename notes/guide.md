# Как устроен проект — для начинающих

Заметка для того, кто учится читать этот код. Пути к файлам даны по ветке `feature/code-cleanup` (самой свежей на 2026-10-19). После проверки на телефоне её сольют в основную ветку. Основа — карта проекта из ревью кода ([[research/code-review]], раздел 2), обновлённая после чистки.

## Где что лежит
```
apps/mobile/                  оболочка приложения
  index.js, app-entry.js      вход; app-entry регистрирует Android-виджет «Баланс»
  modules.ts                  список модулей = вкладки внизу
  app/_layout.tsx             миграции базы → prepare модулей → экраны; потом onReady
  app/(tabs)/finance/*.tsx    маршруты «Финансов»: по 1–3 строки, отдают экран из пакета
  app/(tabs)/health/*.tsx     то же для «Здоровья»
packages/core/                общее для всех модулей: тип AppModule, тема (theme.ts),
                              TextField, Chip, PrimaryButton, SegmentedControl,
                              useAsyncData / useRefreshOnFocus, экран «ошибка в модуле»
packages/db/                  таблицы (src/schema.ts), подключение (src/client.ts), миграции (drizzle/)
packages/finance/src/
  screens/                    экраны: главный, форма записи, счета, бюджеты
  components/                 вкладки Записи / Графики / Отчёты, диаграммы, календарь
  lib/                        всё без экрана: деньги, даты, проверки форм, запросы к базе
  widget/                     Android-виджет
packages/health/src/          так же: screens, components, lib (замеры, подсказки, Health Connect)
notes/                        память проекта (эти заметки)
```
Правило слоёв: **маршрут → экран → функции `lib/` → база**. Экран не пишет запросы к базе сам, он вызывает функции из `lib/`. Модули друг друга не импортируют. Общее лежит в `packages/core` или `packages/db` (`CLAUDE.md`).

## С чего начать чтение
1. `apps/mobile/modules.ts` — какие модули есть.
2. `packages/finance/src/module.ts` — что модуль делает при запуске.
3. `packages/finance/src/screens/FinanceScreen.tsx` — главный экран «Финансов».
4. Чистые функции и тесты рядом с ними — проще всего:
   - `lib/money.ts` и `lib/money.test.ts`;
   - `lib/period.ts`;
   - `lib/records.ts`;
   - `lib/validation.ts` и `lib/validation.test.ts`.

   Тест — это готовый пример: что подать функции и что она вернёт.

## Что происходит, когда нажимаешь «Сохранить» в новой записи
1. Кнопка «+» на главном экране «Финансов» ведёт на адрес `/finance/add-transaction`.
2. Маршрут `apps/mobile/app/(tabs)/finance/add-transaction.tsx` отдаёт экран `AddTransactionScreen` (`packages/finance/src/screens/TransactionFormScreen.tsx`).
3. Экран загружает счета и категории — `getTransactionFormData` в `lib/transactions.ts` — и показывает поля.
4. «Сохранить» вызывает `handleSave`:
   - `checkTransactionForm` (`lib/validation.ts`) проверяет ввод и превращает «12,50» в 1250 копеек;
   - `addTransaction` (`lib/transactions.ts`) записывает строку в таблицу `transactions`;
   - `runAfterTransactionChange` (`lib/afterChange.ts`) обновляет виджет и проверяет бюджет. Если сломается это — запись всё равно сохранится;
   - если не удалась сама запись, под формой появится «Не удалось сохранить запись».
5. Форма закрывается. Вкладка «Записи» снова на экране, `useRefreshOnFocus` перечитывает записи месяца, и новая строка появляется в списке.

## Словарик
- **Модуль** — пакет с одной функцией приложения и своей вкладкой («Финансы», «Здоровье»).
- **Маршрут** — файл в `apps/mobile/app/`: путь к файлу и есть адрес экрана (так работает expo-router).
- **Компонент** — функция, которая возвращает кусок интерфейса.
- **Хук** — функция React с именем `use…`: хранит состояние или запускает действие внутри компонента.
- **Чистая функция** — результат зависит только от входных данных, без базы и без экрана. Её легко тестировать.
- **drizzle** — библиотека для запросов к базе SQLite на TypeScript.
- **Миграция** — SQL-файл, который меняет устройство базы при обновлении и не теряет данные.
- **ErrorBoundary** — «предохранитель»: если модуль упал, вместо его экранов показывается «В модуле произошла ошибка», остальное работает.
- **Копейки (минимальные единицы)** — суммы хранятся целыми числами: 12,50 BYN = 1250. Так не бывает ошибок округления дробей.
- **Тест** — маленькая программа, которая проверяет функцию на примерах.
- **Линтер** — программа, которая сама ищет типичные ошибки в коде.
- **Коммит** — одно сохранённое изменение кода с описанием «что и зачем».
- **Ветка** — отдельная линия изменений, чтобы новую функцию проверить, не трогая рабочую версию.

## Откуда что берётся
- **Почему код написан так** — комментарий рядом с неочевидным местом. Например, в `DateField.tsx` объяснено, почему «вчера» считается как «полдня назад».
- **Почему принято решение** — [[decisions]]: каждое решение с датой и ссылками на источники.
- **Что изменилось и зачем** — сообщения коммитов. На GitHub: вкладка Commits, выбрать ветку.
- **Исследования и проверка фактов** — папка `research`.

## Как проверить самому
Все команды запускаются в папке проекта на компьютере, где установлены Node.js и pnpm:
- `pnpm test` — проверка типов в тестах и все тесты (на 2026-10-19 их 50);
- `pnpm lint` — линтер;
- `cd apps/mobile && pnpm typecheck` — проверка типов всего приложения;
- `cd apps/mobile && pnpm web` — приложение в браузере на http://localhost:8081.

Если всё прошло без ошибок, код хотя бы собирается и проходит проверки. Работу на телефоне это не заменяет.
