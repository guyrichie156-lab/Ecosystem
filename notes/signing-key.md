# Свой ключ подписи и переход на «by.hata.app»

Инструкция для пользователя, 2026-10-24. Подробности и источники — [[research/security-legal]], разделы 1.1 и 1.2.
Решения: ключ живёт только на компьютере пользователя (2026-10-19), имя пакета — `by.hata.app` (2026-10-24).

## Зачем
- Сейчас APK подписан общим учебным ключом шаблона Expo. Его знает кто угодно, поэтому любой может выпустить «обновление» нашего приложения. Google Play такой ключ не принимает ([developer.android.com](https://developer.android.com/studio/publish/app-signing)).
- Новое имя пакета `by.hata.app` — для телефона это новое приложение. Поэтому имя и ключ меняются вместе, а данные переносятся один раз — через «⚙ Настройки → Резервная копия».

## Шаг 1. Сделать копию в старой «Хате»
1. Поставить APK из ветки `apk` со старым именем пакета и «Резервной копией» (поверх, данные сохранятся).
2. ⚙ → «Сделать копию» → записать ключ восстановления (менеджер паролей или бумага).
3. «Сохранить файл» → например, Telegram «Избранное» или «Загрузки».

## Шаг 2. Создать ключ на компьютере (один раз)
1. **Инструменты.** Установить Android Studio ([developer.android.com/studio](https://developer.android.com/studio), бесплатно). В ней есть `keytool` (папка `jbr\bin` внутри Android Studio). Затем в Android Studio: SDK Manager → вкладка SDK Tools → Android SDK Build-Tools 36 — в них `apksigner`. SDK по умолчанию лежит в `%USERPROFILE%\AppData\Local\Android\Sdk`.
2. **Папка для ключа** — вне папки проекта и вне OneDrive, например `C:\Users\<имя>\hata-keys`.
3. **Создать ключ** (PowerShell в этой папке; путь к `keytool.exe` подставить свой):
   ```
   keytool -genkeypair -v -storetype PKCS12 -keystore hata-release.p12 -alias hata -keyalg RSA -keysize 2048 -validity 10000 -dname "CN=Hata"
   ```
   - Программа спросит пароль дважды. Длинный, из менеджера паролей. **Пароль никогда не писать в чат, в Git или в заметки.**
   - `CN=Hata` — имя в сертификате; его видит любой, у кого есть APK, поэтому без ФИО и почты.
   - 10000 дней ≈ 27 лет.
4. **Отпечаток:** `keytool -list -v -keystore hata-release.p12` → строку `SHA256:` прислать Claude. Это публичные данные: по ним проверяются будущие APK.
5. **Копии:** файл ключа — в трёх местах (папка на ПК, менеджер паролей, флешка дома), пароль — отдельно от файла. Ключ потерян — обновить «Хату» поверх уже нельзя.

## Шаг 3. Подписать APK «by.hata.app» (каждый выпуск)
0. **Облачный файл `by.hata.app` без своей подписи на телефон не ставить:** потом подписанный поверх него не встанет.
1. Скачать APK из ветки `apk` и сверить контрольную сумму: `Get-FileHash .\файл.apk` — должна совпасть с той, что написал Claude. Чужой файл не подписывать.
2. Подписать (пути подставить свои):
   ```
   apksigner sign --ks C:\Users\<имя>\hata-keys\hata-release.p12 --ks-key-alias hata --out hata-подписанный.apk файл.apk
   apksigner verify -v --print-certs hata-подписанный.apk
   ```
   SHA-256 сертификата в выводе должен совпасть с отпечатком из шага 2.4.

## Шаг 4. Перенести данные
1. Поставить подписанный APK. На телефоне появится вторая «Хата» (версия 1.1.0) — пустая.
2. Открыть новую → ⚙ → «Восстановить из копии» → файл из шага 1 → ключ восстановления → «Восстановить» дважды.
3. Сверить: счета и итоги месяца, вес, тренировки, еда.
4. Заново дать разрешения: Health Connect, уведомления; заново поставить виджет — система их не переносит (Мнение).
5. Удалить старую «Хату»: Настройки телефона → Приложения → «Хата» версии 1.0.0 → Удалить.
6. Файл копии через неделю удалить из Telegram и Диска (Мнение).

## Что проверено
- Копия и восстановление проверены в браузере (2026-10-24): данные вернулись, неверный ключ, чужой файл и короткий ключ отклоняются. На телефоне ещё не проверено.
- Переподпись облачного APK командой `apksigner sign` проверена агентом на пробном ключе (2026-10-22, [[research/security-legal]], 1.1).
